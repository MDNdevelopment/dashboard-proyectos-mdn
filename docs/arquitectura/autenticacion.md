# Autenticación

|---|---|
|---|---|
| **Propósito** | Login, logout, recuperación y reseteo de contraseña. Carga el perfil del usuario (`userProfile`) y los permisos de módulo (`modulePermissions`) que gobiernan el acceso en toda la app. |
| **Archivos principales** | `src/context/AuthContext.jsx` (provider + `useAuth` + `can()`) · `src/lib/viewAs.js` + `src/lib/viewOnlyClient.js` + `src/components/ViewAsBanner.jsx` (modo "Ver como") · `src/components/ProtectedRoute.jsx` · `src/components/RequireModule.jsx` · `src/lib/permissions.js` (`canAccessModule`) · `src/utils/needsPasswordSetup.js` · `src/config/modules.js` (registro central) · `src/pages/LoginPage.jsx` · `src/pages/ForgotPasswordPage.jsx` · `src/pages/ResetPasswordPage.jsx` |
| **Tablas** | `auth.users` (Supabase Auth) · `users` (perfil: `user_id, first_name, last_name, email, department_id→departments, position_id→positions, company_id, access_level, admin, avatar_url, receive_ticket_notifications, monthly_salary numeric, on_probation boolean (período de prueba, §2.6), deleted_at timestamptz, baja_incluye_mes boolean (¿el mes de la baja cuenta en reportes?, §2.6)`) · `module_permissions` (reglas de acceso por módulo) |
| **Contexto Auth** | `userProfile` (perfil **efectivo**: el real, o el suplantado en modo "Ver como") · `realUserProfile` / `isViewingAs` / `startViewAs(userId)` / `stopViewAs()` (modo "Ver como", ver §Modelo de permisos) · `modulePermissions` (mapa `{[capability_key]: {rules:[]}}`) · `can(capabilityKey)` → boolean — evalúa cualquier clave de capacidad (`empresa`, `empresa.clientes`, `empresa.lineas.manage`, etc.) contra el perfil actual · `accountDisabled` (bool) — igual patrón que `sessionExpired`, true cuando `fetchUserProfile` detecta `users.deleted_at` no nulo (empleado archivado, §2.6): cierra la sesión y `LoginPage` muestra "cuenta deshabilitada". Defensa en profundidad server-side en `netlify/functions/_lib/requireAdmin.js`/`requireUser.js` (rechazan con 401 si el caller está archivado) y baneo real en `auth.users` vía `archive-employee.js`. |
| **Rutas** | `/login` · `/forgot-password` · `/reset-password` |
| **Permisos** | Público (sin sesión) |
| **Invitación de empleados** | `create-employee.js` invita con `inviteUserByEmail(email, { redirectTo: '.../reset-password', data: { must_set_password: true } })`. La bandera queda en `user_metadata`; `ProtectedRoute` la lee vía `needsPasswordSetup(session)` y redirige a `/reset-password` en vez del dashboard mientras siga en `true`. `ResetPasswordPage` detecta el modo invitación por esa misma bandera (copy "Te damos la bienvenida", botón "Crear contraseña"), y al guardar hace `updateUser({ password, data: { must_set_password: false } })` sin `signOut` — entra directo al dashboard (en el flujo normal de recuperación sí hace `signOut` y redirige a `/login`, sin cambios). Plantilla de correo de marca en `supabase/templates/invite.html` (pegar manualmente en Supabase → Authentication → Emails → "Invite user", igual que `recovery.html` para "Reset Password"). |
